鍩虹蹇呭第 1 课

PySide6、Qt 和你的 Python 程序是什么关系？

本节只学三件事
  1. 说清 Qt 与 PySide6 的关系。
  2. 知道 QWidget 是界面对象的基础类型。
  3. 知道下一课为什么先创建 QApplication。

Qt 是负责窗口、绘制、输入和事件分发的跨平台界面框架；PySide6 是让 Python 能调用 Qt 的绑定包。你在代码里持有的是 QLabel、QApplication 等 Python 对象；调用它们的方法时，PySide6 会把请求交给底层 Qt。Python 负责表达你的意图，Qt 负责实际的桌面界面行为。

运行前准备
  1. 在项目目录激活准备运行示例的虚拟环境。
  2. 安装：python -m pip install PySide6。
  3. 依次执行下面三条命令；始终使用同一个 python，避免安装到另一个环境。
python --version
python -m pip show PySide6
python -c "import PySide6; print(PySide6.__version__)"

python --version 应输出类似 Python 3.11.9；第二条应显示 Name、Version、Location 等包信息；第三条应只打印一个版本号，例如 6.8.0。若看到 No module named PySide6，用同一条 python -m pip install PySide6 安装。若 Location 不在当前虚拟环境，先重新激活环境，再安装。若 pip 报当前 Python 不受支持，请安装 PySide6 支持的较新 CPython 版本，重建虚拟环境后重试。

本节只学三件事
  1. 先创建且只创建一个 QApplication。
  2. 创建 QLabel、设置大小并让它显示。
  3. 让 app.exec() 接管等待事件的工作。
运行前准备

确认上一课的导入命令成功。把下面完整程序保存为 first_window.py，在包含该文件的终端执行 python first_window.py；不要把代码逐行贴进交互式解释器。

import sys

from PySide6.QtWidgets import QApplication, QLabel

app = QApplication(sys.argv)
label = QLabel("你好，PySide6！")
label.resize(320, 120)
label.show()
exit_code = app.exec()
raise SystemExit(exit_code)
运行后应该看到什么

桌面上会出现一个约 320×120 像素的窗口，里面显示“你好，PySide6！”。窗口会保持可点击、可拖动；关闭它后，终端回到提示符且程序以 Qt 返回的退出码结束。

程序按什么顺序运行
  1. Python 从上到下导入模块，再创建应用对象和标签。
  2. show() 向 Qt 请求把标签窗口显示到屏幕上；此时 Python 仍会继续执行下一行。
  3. app.exec() 启动事件循环，Qt 才开始持续处理系统发来的重绘、鼠标、键盘和关闭事件。
  4. 关闭最后一个窗口后，事件循环返回退出码，SystemExit 结束 Python 进程。
逐行解释
代码这一行的职责
import sys导入标准库模块，以便取得启动命令附带的参数。
from PySide6... import QApplication, QLabel导入应用管理器和能显示文字的控件类。
app = QApplication(sys.argv)sys.argv 是命令行参数列表；Qt 可读取其中的应用参数。一个桌面 Qt 应用只能有一个 QApplication，因为它集中管理应用级设置和事件分发。
label = QLabel(...)创建文字控件；没有父控件时，它可以作为顶层窗口。
label.resize(320, 120)请求窗口初始宽、高各为 320、120 像素。
label.show()请求 Qt 显示窗口。显示是一次动作，不负责持续等待用户操作。
exit_code = app.exec()开始事件循环并暂停这条 Python 执行路径，直到循环结束；返回值是应用结束时的状态码，通常 0 表示正常退出。
raise SystemExit(exit_code)把 Qt 的退出状态交还给操作系统。这里使用异常只是 Python 进程的标准退出机制。
两处空行不执行代码，只把导入、创建和运行阶段分开，方便观察结构。
关键语法放大镜

from 包.模块 import 名称 只把需要的类带入当前文件。QApplication(sys.argv) 是构造调用：先创建对象，再把引用存到 app。label.show() 的括号表示立刻调用方法；app.exec() 与它分开，是因为“请求显示”与“循环等待事件”是两件不同的事。

对象关系

Python 进程 → QApplication → QLabel → 事件循环。进程持有 app 和 label；app 的事件循环把系统事件送到当前可见的 label。

鍩虹蹇呭第 3 课

为什么 app.exec() 不会让程序卡住？

事件循环持续接收点击、键盘和重绘请求，再分发给相应对象。
本节只学三件事
  1. 区分从上到下执行的 Python 语句和事件驱动的回调。
  2. 用 QTimer.singleShot 安排一次未来的工作。
  3. 识别三个最常见的窗口启动错误。
运行前准备

保存为 event_loop_timer.py 并运行 python event_loop_timer.py。这是完整程序：定时器不会阻塞 Python；它只登记一个三秒后的回调，真正调用发生在事件循环运行期间。

import sys

from PySide6.QtCore import QTimer
from PySide6.QtWidgets import QApplication, QLabel

app = QApplication(sys.argv)
label = QLabel("等待 3 秒…")
label.resize(320, 120)
label.show()

def update_message():
    label.setText("三秒到了：事件循环调用了这个函数。")

QTimer.singleShot(3000, update_message)
exit_code = app.exec()
raise SystemExit(exit_code)
运行后应该看到什么

窗口先显示“等待 3 秒…”，约三秒后自动变成“三秒到了：事件循环调用了这个函数。”；窗口在这段时间仍然能拖动和关闭。

程序按什么顺序运行
  1. Python 先执行到 QTimer.singleShot，只登记 update_message，并不立刻调用它。
  2. 接着 Python 调用 app.exec()，事件循环开始等待事件。
  3. 三秒到期时，事件循环调用 update_message；回调修改标签文字。
  4. 关闭窗口时，关闭事件也由同一个事件循环处理，随后 exec() 返回。
逐行解释

QTimer.singleShot(3000, update_message) 中的 3000 是毫秒，第二个参数是函数对象，不写括号；写成 update_message() 会在登记时立即执行。事件循环不是“卡住”：它是在等待时把控制权交给 Qt，收到计时器、鼠标、键盘或关闭事件后，选择相应回调运行。

关键语法放大镜

def update_message(): 只定义函数。传给 singleShot 的是函数本身；稍后 Qt 再调用它。这是事件驱动与普通顺序调用的关键差别。

对象关系

Python 进程 → QApplication → QLabel；QTimer 向 QApplication 的事件循环登记回调，循环到时调用 update_message，后者更新 QLabel。

改一个地方看变化

把 3000 改成 1000，再把回调中的文字改成自己的提醒。比较两次运行：Python 的登记顺序没有变，变化的是事件循环多久后调度回调。

常见错误
错误写法与症状原因、修复与验证

症状：程序在运行，但没有窗口。

原因：创建控件不会自动显示。修复：在 exec() 前加入 label.show()。验证：运行后应看到窗口，关闭它后终端返回。

label = QLabel("一闪而过")
label.show()

症状：脚本立刻结束，窗口可能一闪而过或根本看不到。

原因：没有事件循环，Python 很快执行到文件末尾。修复：加入 exit_code = app.exec() 和 raise SystemExit(exit_code)。验证：窗口会一直保留到你关闭它。

原因：控件需要应用对象提供的 Qt 环境。修复：先写 app = QApplication(sys.argv)，再构造 QLabel。验证：重排后运行不再报该错误并能显示窗口。

用控件收集输入并显示结果

本节只学三件事
  1. 把 QLabel、QLineEdit、QComboBox、QPushButton 和 QTextEdit 组成一个完整表单。
  2. 用构造参数给控件初始文字，用 text()/currentText() 读取值，再用 setText() 写入值。
  3. 在窗口类中把以后还要使用的控件保存为 self.属性。
运行前准备

保存为 widgets_form.py，确认已安装 PySide6 后运行 python widgets_form.py。这是完整程序，不要把类的一部分单独复制到交互式解释器。

import sys

from PySide6.QtCore import Slot
from PySide6.QtWidgets import QApplication, QComboBox, QFormLayout, QLabel, QLineEdit, QPushButton, QTextEdit, QVBoxLayout, QWidget

class ProfileForm(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("控件表单")
        self.name_input = QLineEdit("小林")
        self.role_box = QComboBox()
        self.role_box.addItems(["检修员", "分析员", "管理员"])
        self.submit_button = QPushButton("显示资料")
        self.result_output = QTextEdit()
        self.result_output.setReadOnly(True)
        form = QFormLayout()
        form.addRow(QLabel("姓名："), self.name_input)
        form.addRow(QLabel("角色："), self.role_box)
        layout = QVBoxLayout(self)
        layout.addLayout(form)
        layout.addWidget(self.submit_button)
        layout.addWidget(self.result_output)
        self.submit_button.clicked.connect(self.show_profile)

    @Slot()
    def show_profile(self):
        name = self.name_input.text().strip()
        role = self.role_box.currentText()
        self.result_output.setText(f"已提交：{name}（{role}）")

app = QApplication(sys.argv)
window = ProfileForm()
window.resize(360, 250)
window.show()
raise SystemExit(app.exec())
运行后应该看到什么

窗口从上到下有四个可见区域：第一行是“姓名：”标签和预填“小林”的单行输入框；第二行是“角色：”标签和默认“检修员”的下拉框；第三行是“显示资料”按钮；最后是一块空白、不可编辑的多行结果框。改姓名或选择角色后点击按钮，最后一行会变成例如“已提交：王敏（分析员）”；前面三行仍保留当前输入。

程序按什么顺序运行
  1. ProfileForm() 依次创建所有控件和布局。
  2. QLineEdit("小林") 与 QPushButton("显示资料") 的字符串是构造参数，创建时就给出初始文字。
  3. clicked.connect(...) 只登记将来的处理方法；app.exec() 开始等待用户操作。
  4. 点击按钮后，槽函数读取两个控件，再更新只读的 QTextEdit。
逐行解释
代码作用
self.name_input = QLineEdit("小林")创建单行编辑框并保存实例引用；槽函数可用同一对象的 text() 读取内容。
self.role_box.addItems(...)把多个选项放入下拉框；currentText() 返回当前可见文字。
self.result_output.setReadOnly(True)结果框仍能显示和复制文本，但用户不能直接编辑它。
setText(...)setter：把新文本写到控件；与返回当前值的 getter text() 相对。
关键语法放大镜

self.name_input 左侧把对象引用存到窗口实例，右侧才是构造 QLineEdit。局部变量在构造方法结束后不再是该窗口可访问的名字；需要在按钮回调中读取的控件应保存在 self 上。text() 和 currentText() 有括号，表示“现在取值”；setText(value) 则把值交给控件显示。

对象关系

ProfileForm 持有输入框、下拉框、按钮和结果框；布局持有它们的摆放关系。按钮的 clicked 信号到达 show_profile，槽从输入控件读取值，写入结果控件。

改一个地方看变化

from PySide6.QtCore import Slot
from PySide6.QtWidgets import QApplication, QLabel, QPushButton, QVBoxLayout, QWidget

class CounterWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.count = 0
        self.count_label = QLabel("计数：0")
        self.increment_button = QPushButton("加一")
        layout = QVBoxLayout(self)
        layout.addWidget(self.count_label)
        layout.addWidget(self.increment_button)
        self.increment_button.clicked.connect(self.increment)

    @Slot()
    def increment(self):
        self.count += 1
        self.count_label.setText(f"计数：{self.count}")

app = QApplication(sys.argv)
window = CounterWindow()
window.resize(220, 120)
window.show()

运行后应该看到什么

窗口先显示“计数：0”和“加一”按钮。第一次点击后标签变成“计数：1”，以后每点击一次递增一次；按钮文字和窗口布局不改变。

程序按什么顺序运行
  1. 构造窗口时先建立 count、标签和按钮，再把方法对象登记到 clicked 信号。
  2. 程序进入事件循环后什么也不会自动递增。
  3. 用户释放鼠标按钮时，clicked 发射；Qt 在那一刻调用已登记的 increment。
  4. 槽增加 Python 状态并用新值更新标签。
逐行解释
代码作用
self.increment_button.clicked.connect(self.increment)把“可在以后调用的绑定方法对象”存进信号的连接表；这里没有括号。
@Slot()把下面方法声明为 Qt 槽；这个无参数槽只关心自己的窗口状态。
self.count += 1改变保存在实例上的状态，所以下次点击仍能看见上一次的计数。
setText(f"...")把最新状态渲染到可见标签，而不是只在 Python 变量中改变数字。
关键语法放大镜

connect(self.increment) 传递的是函数对象，意思是“请 Qt 稍后调用它”。connect(self.increment()) 先在构造期间执行 increment()，其返回值（通常是 None）才被拿去连接，因此会过早更新或连接失败。clicked 可自动携带一个 checked 布尔参数；本例的无参 @Slot() 不需要它，Qt 会匹配这个槽。若确实要捕获循环中的额外值，可写 button.clicked.connect(lambda checked, value=value: self.choose(value))：lambda 显式接住自动传来的 checked，并冻结当前 value。初学的单按钮动作仍优先使用命名槽。

对象关系

CounterWindow 持有计数、标签和按钮。按钮持有 clicked 信号到 increment 的连接；事件循环在点击发生时调用槽，槽再更新窗口持有的标签。

常见错误
错误原因、修复与验证
clicked.connect(self.increment())括号会使槽在连接阶段提前运行，并传入 None。修复为 clicked.connect(self.increment)；验证：启动窗口仍为 0，点击后才变 1。
每次点击或刷新界面都再次执行 connect同一个信号会累计多个连接，之后一次点击可能加多次。修复：通常只在构造方法连接一次；验证：连续点击五次时计数严格为 5，而不是跳跃。

    def __init__(self):

        layout.addWidget(self.reset_button)

    def choose_file(self):

完整线程池示例

这个例子把工作结果、错误和收尾分别用信号送回主线程。run() 内没有任何 QWidget 调用。

import sys
import time
import traceback

from PySide6.QtCore import QObject, QRunnable, QThreadPool, Signal, Slot
from PySide6.QtWidgets import QApplication, QLabel, QLineEdit, QPushButton, QVBoxLayout, QWidget


class WorkerSignals(QObject):
    result = Signal(str)
    error = Signal(str)
    finished = Signal()


class DemoDiagnosisService:
    def diagnose(self, filename):
        time.sleep(0.4)
        return f"{filename}：模拟诊断完成，置信度 92%"


class DiagnosisRunnable(QRunnable):
    def __init__(self, service, filename):
        super().__init__()
        self.service = service
        self.filename = filename
        self.signals = WorkerSignals()

    @Slot()
    def run(self):
        try:
            if not self.filename.strip():
                raise ValueError("请输入文件名")
            result = self.service.diagnose(self.filename)
            self.signals.result.emit(result)
        except Exception:
            self.signals.error.emit(traceback.format_exc())
        finally:
            self.signals.finished.emit()


class ThreadPoolWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("线程池诊断演示")
        self.pool = QThreadPool.globalInstance()
        self.service = DemoDiagnosisService()
        self.task = None
        self.filename_input = QLineEdit("signal.txt")
        self.start_button = QPushButton("在线程池中诊断")
        self.status_label = QLabel("空闲")
        self.start_button.clicked.connect(self.start_task)
        layout = QVBoxLayout(self)
        for widget in (self.filename_input, self.start_button, self.status_label):
            layout.addWidget(widget)

    @Slot()
    def start_task(self):
        self.start_button.setEnabled(False)
        self.status_label.setText("后台工作中…")
        self.task = DiagnosisRunnable(self.service, self.filename_input.text())
        self.task.signals.result.connect(self.show_result)
        self.task.signals.error.connect(self.show_error)
        self.task.signals.finished.connect(self.finish_task)
        self.pool.start(self.task)

    @Slot(str)
    def show_result(self, text):
        self.status_label.setText(text)

    @Slot(str)
    def show_error(self, text):
        self.status_label.setText(f"失败：{text.splitlines()[-1]}")

    @Slot()
    def finish_task(self):
        self.start_button.setEnabled(True)
        self.task = None


app = QApplication(sys.argv)
window = ThreadPoolWindow()
window.resize(420, 160)
window.show()
raise SystemExit(app.exec())

线程边界：QRunnable 不是 QObject，没有 QObject thread affinity；线程池只决定它的 run() 在哪个工作线程执行。WorkerSignals 在 GUI 主线程创建，它的 affinity 不会因被 runnable 持有而自动迁移。换句话说，run() 的执行线程和 signals 对象的 affinity 是不同概念。

窗口及标签属于 GUI 主线程，WorkerSignals 只传递数据。Qt 会把连到窗口槽的跨线程信号排队，随后在主线程调用 show_result() 或 show_error()。因此 run() 可以计算、读取、构造结果，却绝不能 setText()。

traceback.format_exc() 将异常转换成字符串，再经 error 信号传回；finished 放在 finally 中，保证无论成功或失败，主线程的 finish_task() 都能恢复按钮并释放任务引用。

五个常见失败模式

  • 在槽函数里同步 time.sleep()：主线程停止处理鼠标、重绘和定时器。把耗时工作移入 QRunnable.run()。
  • 在 run() 里访问 QWidget：线程亲和性错误，可能随机崩溃或显示异常。只发普通数据，由主线程槽更新控件。
  • 没有 error 信号：异常只留在后台，用户只看见永不结束的“工作中”。转换为字符串并显示可读错误。
  • 重复启动任务：一次点击一个任务会互相覆盖状态。开始时立刻禁用按钮，并只在 finished 后恢复。
  • 失败后永不恢复按钮：把收尾逻辑写在成功分支会漏掉异常。工作者用 finally 发 finished，主线程统一清理。

PySide6：不只会“摆控件”

PySide6 是 Qt 6 的官方 Python 绑定。Qt 是 C++ GUI 框架，PySide6 让 Python 可以创建 Qt 对象、连接信号槽并进入 Qt 的事件循环。

1. QApplication 与事件循环

桌面程序不是从上到下一次执行完就退出。创建窗口后，app.exec() 开始持续等待鼠标、键盘、计时器、窗口重绘和线程信号，这就是事件循环。

最小窗口
import sys
from PySide6.QtWidgets import QApplication, QLabel

app = QApplication(sys.argv)  # 整个进程通常只有一个
label = QLabel("你好，PySide6")
label.resize(320, 120)
label.show()

raise SystemExit(app.exec())  # 从这里开始等待事件

2. QWidget、QMainWindow 与对象树

QWidget

绝大多数可见控件的基类，也可作为普通容器。QLabel、QPushButton 都是 QWidget。

QMainWindow

专门做主窗口，提供 central widget、菜单栏、工具栏、状态栏和 dock 区域。普通页面不要都继承它。

Qt 使用父子对象树管理生命周期：子控件有父对象后，父对象销毁时会清理子对象。把临时窗口只存在局部变量里却没有合适父对象，可能导致它很快被 Python 回收。

3. 布局管理器：让尺寸自动适应

不要依赖每个控件的固定 x/y 坐标。QVBoxLayout 垂直排列，QHBoxLayout 水平排列，QGridLayout 网格排列，QFormLayout 适合标签—输入框。

4. 信号与槽：Qt 的“通知机制”

信号（Signal）表示某件事发生了；槽（Slot）是收到通知后执行的函数。按钮不需要知道你的业务逻辑，只负责发出 clicked。

连接内置信号
from PySide6.QtCore import Slot

self.start_button.clicked.connect(self.choose_file)

@Slot()
def choose_file(self):
    print("用户点击了按钮")

# 注意：connect 里传函数对象，不加括号。
# 错误：clicked.connect(self.choose_file())
最常见错误：多次 connect如果刷新页面时重复执行 button.clicked.connect(...)，一次点击可能触发多次。通常在构造函数中连接一次。

5. 为什么诊断必须放到后台线程？

Qt 主线程同时负责处理输入和重绘。如果按钮槽里直接读取大文件、计算特征、加载模型，事件循环无法及时处理重绘，窗口就会“未响应”。

主线程点击按钮
→
线程池执行 QRunnable
→
Signal跨线程传结果
→
主线程更新控件
与本项目 workers.py 同样的模式
from PySide6.QtCore import QObject, QRunnable, QThreadPool, Signal, Slot

class WorkerSignals(QObject):
    result = Signal(object)
    error = Signal(str)
    finished = Signal()

class DiagnosisTask(QRunnable):
    def __init__(self, service, path):
        super().__init__()
        self.service = service
        self.path = path
        self.signals = WorkerSignals()

    @Slot()
    def run(self):
        try:
            result = self.service.diagnose_file(self.path)
            self.signals.result.emit(result)
        except Exception as exc:
            self.signals.error.emit(str(exc))
        finally:
            self.signals.finished.emit()

task = DiagnosisTask(service, path)
task.signals.result.connect(self.show_result)
QThreadPool.globalInstance().start(task)
线程铁律工作线程做计算和 I/O；主线程更新 QWidget。不要在 run() 中直接调用 label.setText()，应当发信号。

改动 B：给 SDK 增加一个能力

先决定它是否真的是稳定公共能力。例如新增 validate_file(path)：

  1. 在最靠近职责的位置实现，如 signal_io.py。
  2. 在 engine.py 提供调用门面，不让用户拼装内部步骤。
  3. 为成功和失败路径添加测试。
  4. 如果希望外部用户直接导入，在 __init__.py 中导出。
  5. 更新 docs/API.md，说明参数、返回值和异常。
不要随便修改返回类型给 DiagnosisResult 增加有默认值的字段通常比删除/改名安全。公共 API 变更需要考虑已有脚本。
改动 C：新增一个 UI 页面
  1. 新页面优先独立为 QWidget 子类，复杂时放入单独文件。
  2. 把它加入 QStackedWidget。
  3. 侧栏按钮只负责切换对应索引。
  4. 页面需要数据时，通过构造参数注入 service/repository。
  5. 长任务仍通过 worker，不在点击槽中同步执行。

当 main_window.py 继续增长时，可以拆成 ui/pages/diagnosis_page.py、batch_page.py、history_page.py。拆分依据是职责和依赖，不是机械地规定每个文件多少行。

改动 D：升级模型或特征
  1. 固定训练数据和实验配置，训练新模型。
  2. 若特征定义/顺序变化，升级 feature schema。
  3. 生成新的权重、scaler 和 manifest，更新模型版本。
  4. 校验哈希和类别连续 ID。
  5. 运行回归测试，并用真实样例验收。
  6. 保留旧 bundle，便于回滚和结果追溯。
模型版本为什么写进结果？半年后查看一条历史诊断时，你必须知道它由哪一版模型生成，否则结果无法审计和复现。

当前版本新增的可靠性边界

前面的源码课堂用于解释项目如何从原型演进。下面这些是当前代码已经实现并由测试固定的行为；阅读旧行号示例时，以本节和仓库源码为准。

安装与启动

launcher.py 延迟导入 GUI。默认模型按环境变量 → 仓库 → 安装共享目录解析；wheel 已携带模型三件套和 py.typed。

严格模型契约

bundle.py 校验必填字段、架构、路径不能逃逸、SHA-256、连续且唯一的类别、有限 mean 与严格正 scale，以及可配置置信度阈值。

输入与推理边界

信号验证会复制出独立快照。特征、标准化输入、logits、概率任一层出现 NaN/Inf 都会产生明确 DiagnosisError。

持久化不污染诊断

推理成功但 SQLite 保存失败时仍返回结果并附加警告；保存错误记录失败时仍抛原始诊断异常。日志保留完整 traceback。

线程结果不可变

SingleDiagnosisOutcome 把原路径、只读 samples 与结果绑定。窗口不再按当前输入框二次读取文件，并以窗口私有单线程池串行访问模型。

可用性与大历史

主题、窗口和分栏使用 QSettings 保存；时间转换到本地并按 QLocale 显示；历史每页 100 条，CSV 在后台导出。
