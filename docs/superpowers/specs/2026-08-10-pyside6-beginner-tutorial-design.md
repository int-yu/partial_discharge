# PySide6 初学者教程重构设计

日期：2026-08-10  
目标文件：`docs/educate/index.html`  
目标读者：熟悉 Python 类、类型提示、包和异常，但只掌握少量 PySide6 语法的初学者

## 1. 背景与问题

当前教程已经覆盖 SDK、项目分层、目录结构、源码区块、线程、模型工件、SQLite、练习和自测，也具备离线、响应式、搜索、主题切换等能力。但它更像“项目架构参考手册”，还不是一门适合 PySide6 初学者从头跟学的课程。

主要学习障碍如下：

1. 开篇直接进入 SDK、分层和模型契约，没有先建立 PySide6 最小程序的运行模型。
2. `QApplication`、事件循环、主线程、控件树、布局、信号与槽等概念出现得早，但缺少由小到大的演示。
3. 源码课堂按逻辑区块解释，未逐行说明对象从哪里来、每个参数做什么、语句执行后状态怎样改变。
4. 示例缺少统一的运行前准备、预期界面、失败现象和排错步骤。
5. 练习以真实工程改动为主，跨度较大，初学者无法在每个知识点后立即获得反馈。
6. 基础内容与模型、线程、持久化等进阶内容混排，读者难以判断哪些必须现在掌握，哪些可以以后再看。

本次重构不以单纯增加字数为目标，而是降低每一步的认知负担，让读者能够“复制运行 → 看见结果 → 理解每行 → 修改验证 → 再进入项目源码”。

## 2. 目标与非目标

### 2.1 目标

- 从 PySide6 基础开始，逐步过渡到本仓库的真实桌面应用。
- 默认读者已经理解 Python 类、`self`、类型提示、包、导入和异常，不重复教授这些内容。
- 对关键教学示例进行逐行解释，并解释关键标点、参数、对象关系和执行顺序。
- 每一基础章节都提供可独立运行的完整代码、预期现象、常见错误、最小练习和参考答案。
- 将内容标记为“基础必学”“项目必学”“进阶选学”，明确首次阅读路径。
- 保留并改进现有源码浏览器，使它成为后期查阅工具，而不是课程入口。
- 保持单个 HTML 文件、无网络依赖、双击可读、响应式、可打印和键盘可操作。
- 保留对仓库当前实现的准确描述，不虚构已经不存在的类、方法或调用链。

### 2.2 非目标

- 不教授 Python 基础语法、面向对象入门或类型提示语法。
- 不教授 Qt Designer、QML、C++ Qt 或移动端开发。
- 不深入推导局部放电领域知识、FFT 数学或神经网络训练原理；这些只解释到理解调用边界所需的程度。
- 不修改应用源码、模型、数据集或 SDK 行为。
- 不引入外部框架、CDN、构建工具或服务器。
- 不把教程拆成多个网页。

## 3. 采用方案

采用“单文件、双层信息架构”方案：

- 第一层是线性课程，面向首次学习。它从最小 PySide6 程序开始，每次只增加一个概念，最后构建一个简化诊断界面并接入本项目。
- 第二层是源码参考，面向复习和查找。它保留文件搜索和源码区块导航，并补充阅读前置、初读重点和关键代码逐行解释。

不采用“只在现有章节中追加段落”，因为会继续放大信息密度；不采用多 HTML 文件，因为用户要求在指定位置构建便于离线携带的完整教学文档。

## 4. 信息架构与学习路线

### 4.1 页面入口

首屏直接说明：

- 读者应已掌握哪些 Python 内容；
- 本教程不要求预先掌握哪些 Qt 内容；
- 学完能独立完成什么；
- 三类难度标签的含义；
- 推荐的首次学习路径和预计学习次数。

首屏提供三个入口：

1. “从 PySide6 第一课开始”；
2. “继续上次学习”；
3. “查阅项目源码”。

### 4.2 课程阶段

#### 阶段 A：PySide6 基础必学

1. PySide6、Qt、绑定和桌面 GUI 的关系。
2. 安装、验证环境和第一个空窗口。
3. `QApplication`、`QWidget`、`show()`、`exec()` 与事件循环。
4. 控件对象和父子关系。
5. `QLabel`、`QPushButton`、`QLineEdit`、`QTextEdit`、`QComboBox`、`QListWidget`、`QTableWidget`。
6. `QVBoxLayout`、`QHBoxLayout`、`QGridLayout`、`QFormLayout` 与嵌套布局。
7. 信号、槽、函数对象、带参数信号、`lambda` 和 `@Slot`。
8. `QMainWindow`、中央控件、菜单栏、工具栏和状态栏。
9. 对话框、文件选择和消息框。
10. `QStackedWidget` 与侧栏页面切换。
11. QSS、对象名、动态属性、状态选择器和主题。

#### 阶段 B：从小程序到真实项目

12. 分六步构建“简化诊断界面”：窗口骨架、文件选择、状态切换、结果卡片、页面导航、错误反馈。
13. 为什么耗时操作会卡住窗口：主线程和事件循环。
14. `QRunnable`、`QThreadPool`、工作信号、成功/失败/结束收尾。
15. SDK、API、库、框架和应用的区别。
16. 使用本项目 SDK 完成一次不带 UI 的诊断。
17. 把简化界面与 `DiagnosisService` 的调用方式对应起来。

#### 阶段 C：项目必学

18. 仓库目录地图与推荐阅读顺序。
19. 应用启动链：命令入口 → launcher → QApplication → 依赖创建 → MainWindow → 事件循环。
20. 单文件诊断链：按钮 → 窗口状态 → Worker → Service → Engine → 结果信号 → UI。
21. 主窗口的控件树、页面结构和状态变化。
22. `ui/app.py`、`ui/main_window.py`、`ui/workers.py` 逐文件精读。
23. `engine.py`、`service.py`、`types.py` 逐文件精读。

#### 阶段 D：进阶选学与参考

24. SQLite Repository 和历史分页。
25. 模型 bundle、manifest、哈希、scaler 和版本契约。
26. 输入快照、不可变结果、线程边界和持久化失败隔离。
27. 其余配置、训练、迁移、测试和文档文件的源码浏览器。
28. 综合练习、学习检查表、自测和术语表。

## 5. 单节教学模板

所有基础必学和项目必学章节使用同一模板，避免读者每次重新适应表达方式。

1. **本节只学三件事**：最多列出三个明确目标。
2. **先看最终效果**：用文字线框图或页面内的小型 UI 示意说明运行结果。
3. **运行前准备**：指出文件名、执行目录、命令和需要安装的依赖。
4. **完整可复制代码**：代码必须可独立运行，不使用未定义的省略变量。
5. **程序按什么顺序运行**：用 3～7 步执行时间线说明。
6. **逐行解释表**：每一行包含“行号、代码、白话解释、执行后发生什么”。空行和纯注释可合并说明。
7. **关键语法放大镜**：解释例如 `QApplication(sys.argv)`、`clicked.connect(...)`、`setCentralWidget(...)` 中的对象、点号、参数和返回关系。
8. **对象关系**：说明谁创建谁、谁持有谁、父对象是谁、信号从哪里发出。
9. **改一个地方看变化**：只修改一个文本、尺寸、布局或连接，给出明确预期。
10. **常见错误**：展示错误代码、错误现象、原因和修正代码。
11. **最小练习**：限定在本节知识范围，10～20 分钟可完成。
12. **参考答案**：默认折叠，包含完整代码和验证结果。
13. **过关检查**：用三项自检判断是否进入下一节。

逐行解释不机械解释每个括号，而在第一次出现时详细说明，后续通过“复习链接”指回原解释。这样保持极其详细，同时避免相同知识反复占满页面。

## 6. 源码精读格式

源码浏览器中的每个文件增加以下元数据：

- 难度：基础、项目、进阶；
- 阅读前应掌握的章节；
- 这个文件解决的唯一主要问题；
- 谁调用它、它调用谁；
- 第一次阅读只看哪些类或方法；
- 可以暂时跳过哪些细节。

每个逻辑区块使用以下展示顺序：

1. 原始代码片段；
2. 一句话说明；
3. 输入、输出和副作用；
4. 按行解释；
5. 关键对象当前状态；
6. 为什么这样写；
7. 初学者可能误解的地方；
8. 修改风险；
9. 对应测试或调用位置。

对于长度较大的 `main_window.py`，不要求在同一屏展开全部代码，而是按页面构造、信号连接、输入状态、任务启动、结果展示、历史操作和关闭收尾拆分。每个区块仍引用真实源码路径和当前实现名称。

## 7. 页面组件与视觉层级

保留现有品牌、明暗主题、侧栏、卡片、代码块和响应式布局，并增加：

- 难度徽标：基础必学、项目必学、进阶选学；
- “初读可跳过”提示；
- 课程阶段导航和当前位置；
- 学习进度复选框；
- “继续上次学习”入口；
- 预期界面线框卡片；
- 逐行解释表；
- 正确代码与错误代码的明显区分；
- “尝试修改”实验卡；
- 默认折叠的答案和进阶解释；
- 本节上一课、下一课链接。

正文段落保持较短；一屏只突出一个主要结论。复杂表格在窄屏允许横向滚动，代码块可聚焦、可复制。颜色不作为唯一状态提示。

## 8. 交互与数据流

页面保持两个内联脚本的现有结构：一个保存课程/源码数据，一个负责页面交互。所有文本使用 `textContent` 或预先写入的静态 HTML，避免将数据拼接为不受控的 HTML。

交互数据流如下：

1. 页面加载时读取主题、学习进度和最后章节；
2. 根据保存状态更新进度条、章节复选框和“继续学习”链接；
3. 目录点击只改变滚动位置和当前高亮；
4. 勾选完成章节后写入 `localStorage`；
5. 源码搜索过滤本地 `SOURCE_FILES`，选择文件后渲染元数据和讲解区块；
6. 练习答案只在用户主动展开时显示；
7. 自测提交后显示分数、错题和应复习章节。

若浏览器禁用或限制 `localStorage`，教程内容仍应正常阅读，只是不保存主题和进度。脚本应捕获存储异常，不让整个页面初始化失败。

## 9. 错误教学设计

每个 PySide6 基础章节至少覆盖一个真实常见错误，格式固定为：

- 错误现象；
- 最小错误代码；
- Python 或 Qt 实际在做什么；
- 如何定位；
- 修正后的完整代码；
- 如何确认已经修好。

基础阶段必须覆盖：

- 没有创建 `QApplication` 就创建控件；
- 忘记 `show()`；
- 忘记进入 `exec()`；
- 把 `connect(self.run())` 写成提前调用；
- 局部变量窗口或对话框被回收；
- 一个控件被错误地加入多个布局；
- 没有中央控件就给 `QMainWindow` 直接设置布局；
- 在工作线程更新 QWidget；
- 在槽函数同步执行耗时操作导致界面卡死；
- 捕获异常后没有恢复按钮和进度状态。

项目阶段的错误示例必须与当前项目的公共异常和线程收尾方式一致。

## 10. 测试与验收

### 10.1 自动检查

扩展 `tests/test_education_page.py`，验证：

- 页面仍是 `zh-CN` 单文件离线文档；
- `main`、`nav`、`aside` 等语义结构保留；
- 所有 ID 唯一，内部锚点目标存在；
- 两个内联脚本可通过 Node.js 语法检查；
- 新增 PySide6 基础入口、最小窗口、布局、信号槽、主窗口、多页面、线程和项目桥接章节；
- 每个基础章节具备学习目标、完整代码、逐行解释、预期结果、常见错误、练习和答案；
- 难度标签和进度控件存在；
- 无外部脚本、样式、字体或图片依赖；
- 源码文件数量和讲解区块仍可渲染；
- quiz 的题目数、答案映射和复习链接一致。

### 10.2 内容核对

- 所有可运行示例单独保存到临时文件后进行 Python 语法编译检查。
- 能在已安装 GUI 依赖的环境中对最小示例进行无窗口启动测试时，使用 `QT_QPA_PLATFORM=offscreen` 验证窗口可创建并正常退出。
- 核对教程中的类、方法、源码路径和调用链与仓库当前代码一致。
- 运行教程专项测试后，再运行完整 pytest、Ruff 和 mypy，确认文档改动未破坏项目质量门槛。

### 10.3 人工验收

使用桌面宽屏和手机宽度分别检查：

- 首次打开能明确知道从哪里开始；
- 前三课无需阅读项目源码即可完成；
- 代码和解释能够一一对应；
- 折叠答案不会意外提前显示；
- 刷新页面后可以继续上次章节；
- 禁用 JavaScript 后仍能阅读所有静态核心内容；
- 打印时目录按钮、复制按钮和无关交互不会占据正文。

## 11. 完成标准

满足以下条件才算完成：

1. 教程入口从 PySide6 基础开始，未加入 Python 基础课程。
2. 至少完成从最小窗口到后台任务的渐进式基础路线。
3. 每个基础必学章节均符合统一教学模板。
4. 真实项目内容在基础路线之后出现，并明确连接前面学过的 PySide6 概念。
5. 源码浏览器保留且具有阅读前置、初读重点和更细的解释结构。
6. 页面保持单文件离线、可访问、响应式和可打印。
7. 所有新增与既有自动测试通过，JavaScript 和示例 Python 代码通过语法检查。
8. 数据集和应用实现不因本次教程重构而改变。

## 12. 实施边界

实施时优先复用现有 CSS 变量、卡片、代码框、目录、搜索、主题和源码渲染逻辑。允许为可读性增加新的 HTML 组件和数据字段，但不引入依赖。由于教程是大型单文件，实施应分阶段完成并在每阶段运行结构与脚本检查，避免最后才发现锚点、脚本或数据字面量损坏。
